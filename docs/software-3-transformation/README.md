## Problem

Small and medium businesses often hold critical workflows in messages, spreadsheets, personal knowledge, and disconnected software. Adding an AI chatbot does not fix the operating system. S3T-001 maps the complete workflow, assigns each step to human judgment, deterministic software, machine learning, or language-model reasoning, and places approvals, evidence, tests, and rollback around the resulting system.

## Value proposition

S3T-001 converts an owner-approved workflow into an evidence-controlled AI operating system with:

- current-state audit;
- Software 1.0 / 2.0 / 3.0 classification;
- prioritized automation and agent opportunities;
- target architecture;
- prompt, data, tool, and permission contracts;
- implementation backlog;
- evaluations and acceptance criteria;
- owner gates and rollback.

### Provider policy

Claude remains the default provider. NIM is an optional evaluation provider behind the same prompt contract. Model output must never bypass evidence classification, owner approval, tool permissions, or the evaluation suite. Provider selection is not evidence of model quality.

## Risks

- AI output presented as verified evidence.
- Tool actions exceeding authorization.
- private information copied into third-party products.
- unsupported integrations or model claims.
- provider cost and availability changes.
- prompt drift across platforms.
- premature selling before proof and support readiness.

Mitigation: one canonical prompt, version control, source citations, data classification, permission tests, owner gates, evaluation fixtures, and monthly reviews.

## Success measures

- 100% of outputs label evidence class.
- Zero unauthorized external actions.
- 100% of high-impact outputs require human approval.
- At least 95% pass rate on the approved grounding evaluation set before internal acceptance.
- One measurable workflow outcome: time saved, error reduction, cycle-time reduction, or decision-quality improvement.
- All defects, decisions, and rollback steps documented.

## Environment and deployment impact

This branch adds no secrets, API keys, database migrations, production routes, Vercel deployment, Supabase changes, or client data. NIM and other provider credentials remain absent. Rollback is deletion or reversion of the S3T files and Notion records.
